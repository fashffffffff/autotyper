# autotyper

Кроссплатформенная (macOS / Windows / Linux) утилита: по глобальному хоткею
читает текст из буфера обмена и **печатает** его в активное окно другого
приложения, имитируя живой ручной ввод — со случайной скоростью и
«человеческими» паузами. В отличие от вставки через Ctrl+V, посимвольный
ввод неотличим от набора руками: работает в чатах, веб-формах, редакторах.

## Быстрый старт

### Вариант 1 — готовый бинарник (Rust не нужен)

Скачай архив со [страницы Releases](https://github.com/fashffffffff/autotyper/releases/latest)
и распакуй — внутри уже всё для запуска (бинарник, лаунчер, README,
пример конфига):

| Твоя система | Файл |
|---|---|
| macOS (Apple Silicon, M1–M4) | `autotyper-macos-arm64.tar.gz` |
| macOS (Intel) | `autotyper-macos-intel.tar.gz` |
| Windows | `autotyper-windows-x86_64.zip` |
| Linux | `autotyper-linux-x86_64.tar.gz` |

```bash
# macOS / Linux:
tar -xzf autotyper-<твой-файл>.tar.gz && cd autotyper-*
xattr -d com.apple.quarantine autotyper   # только macOS: снять карантин
                                           # Gatekeeper (сборка без подписи)
./run-macos.command   # или run-linux.sh; на macOS — двойной клик тоже работает

# Windows: распакуй zip → двойной клик по run-windows.bat
# (SmartScreen предупредит о неизвестном издателе: «Подробнее → Выполнить в любом случае»)
```

На macOS один раз выдай терминалу разрешение
**System Settings → Privacy & Security → Accessibility** — без него перехват
хоткеев и синтез ввода молча не работают. На Linux могут понадобиться права
группы `input` (см. [раздел про Linux](#linux)).

### Вариант 2 — собрать из исходников

```bash
git clone https://github.com/fashffffffff/autotyper.git   # или Code → Download ZIP
cd autotyper
cargo build --release        # нужен Rust: https://rustup.rs
cargo run --release          # или ./target/release/autotyper
```

### Дальше — одинаково для обоих вариантов

При первом запуске рядом с бинарником создастся `CONFIG.json` — с
комментарием у каждого параметра. Схема использования: скопировал текст →
перешёл в целевое окно → **Ctrl+V** (macOS) / **Alt+V** (Win/Linux) → текст
печатается посимвольно. Во время печати: **F8** — пауза/продолжение,
**Esc** — полный сброс. Все клавиши меняются в `CONFIG.json`.

Подробности — ниже: [управление](#управление-во-время-печати),
[права для ОС](#права-и-особенности-платформ),
[конфигурация](#конфигурация), [автозапуск](#автозапуск).

## Как это работает

| Роль | Крейт / механизм | Почему |
|------|------------------|--------|
| Перехват глобального хоткея | `rdev` | только прослушивание событий |
| Эмуляция ввода (фокусное окно) | `enigo` | корректный Unicode (кириллица): macOS — `CGEventKeyboardSetUnicodeString`, Windows — `SendInput` + `KEYEVENTF_UNICODE`, Linux — X11 `XTest` |
| Фоновая печать без фокуса (только macOS) | свой бэкенд, `CGEventPostToPid` | события отправляются конкретному процессу — окно не обязано быть в фокусе |
| Чтение буфера обмена | `arboard` | один раз на хоткей, посимвольно буфер **не** трогаем |

Хоткей по умолчанию: **Ctrl+V на macOS** (именно Ctrl, не Cmd — чтобы не
конфликтовать с системной вставкой), **Alt+V на Windows/Linux**.

### Управление во время печати

| Действие | Хоткей по умолчанию | Что происходит |
|----------|--------------------|----------------|
| Печать | Ctrl+V (macOS) / Alt+V (Win/Linux) | читает буфер обмена и печатает |
| **Пауза / продолжение** | **F8** (одиночная клавиша, переключатель) | печать замирает на текущем символе; при возобновлении autotyper проверяет, что фокус вернулся в целевое окно (см. ниже) |
| **Полный сброс** | **Esc** | печать немедленно прекращается и **не продолжается** — прогресс сбрасывается (если начали печатать не туда, жмите это) |

Пауза специально на одиночной клавише без модификаторов: Ctrl+клавиша
перехватывают сами редакторы (Ctrl+A — в начало строки и т.п.) и сбивают
курсор. F8 нейтральна почти везде; не подойдёт —
поменяйте в конфиге (например, на `f9` или `=`).

Проверка фокуса при возобновлении (уровень 1): при старте печати autotyper
запоминает PID приложения в фокусе; если при снятии паузы переднее окно
другое — продолжение отклоняется с подсказкой «вернитесь в целевое окно и
нажмите F8 ещё раз». В фоновом режиме (macOS) проверка не нужна —
печать идёт в конкретный процесс.

```bash
cargo build --release

```

## Права и особенности платформ

### macOS

Обязательно: **System Settings → Privacy & Security → Accessibility** —
добавьте терминал (Terminal/iTerm2), из которого запускаете autotyper,
либо сам бинарник при автозапуске через launchd. Без этого перехват
хоткеев и синтез ввода **молча не работают**. Если события не приходят —
проверьте также **Input Monitoring** для терминала.

### Windows

Специальных прав не нужно (SendInput в пользовательской сессии). Нюанс:
при работе через RDP ввод синтезируется, только пока RDP-сессия активна.

### Linux

* **X11 обязателен**: в Wayland-сессии синтез ввода не работает —
  выберите «Ubuntu на Xorg» и т.п. на экране входа (проверяется при старте:
  autotyper предупредит, если видит `WAYLAND_DISPLAY`).
* **Права на устройства ввода**: пользователь должен быть в группе `input`
  и иметь доступ к `/dev/uinput`:

  ```bash
  sudo usermod -aG input $USER
  # udev-правило для /dev/uinput:
  echo 'KERNEL=="uinput", MODE="0660", GROUP="input"' | \
    sudo tee /etc/udev/rules.d/60-uinput.rules
  sudo udevadm control --reload-rules && sudo udevadm trigger
  # после usermod перелогиньтесь
  ```

* **Unicode на X11 — главное ограничение**: XTest вводит символы через
  текущую раскладку клавиатуры. Латиница работает всегда; **кириллица
  вводится корректно, когда нужные символы достижимы из активных раскладок**
  (обычно достаточно, чтобы в системе была добавлена русская раскладка).
  Если целевое приложение получает не те символы — переключитесь на
  раскладку с нужным алфавитом или рассмотрите ввод через `uinput`
  (создание виртуальной клавиатуры; требует прав, см. выше).

## Конфигурация

**Где настройки:** файл **`CONFIG.json`** (имя капсом — чтобы был заметен)
лежит в одной директории со всем остальным — папка HOME не засоряется:

* при разработке — в корне проекта (рядом с `Cargo.toml`, `README.md`,
  `launchers/`);
* при «портативной» установке — рядом с бинарником (exe + CONFIG.json +
  лаунчер в одной папке);
* если каталог бинарника недоступен на запись (например, `/usr/local/bin`) —
  запасной `~/.config/autotyper/CONFIG.json` (об этом печатается в stderr).

Точный путь печатается в stderr при каждом запуске. Если файла нет — при
первом запуске создаётся дефолтный, **с комментарием у каждого параметра**.

Править нужно только JSON — код скомпилирован, «сломать» его правкой
конфига невозможно. Конфиг поддерживает `//`-комментарии (полные строки и
хвостовые). Шаблон с комментариями: `examples/config.example.json`.

```json
{
  "hotkey": {
    "macos": { "modifiers": ["ctrl"], "key": "v" },
    "other": { "modifiers": ["alt"], "key": "v" }
  },
  "panic_hotkey": { "modifiers": [], "key": "escape" },
  "pause_hotkey": { "modifiers": [], "key": "f8" },
  "type_and_send_hotkey": { "modifiers": ["ctrl", "shift"], "key": "v" },
  "average_speed_cps": 42,
  "speed_variance_percent": 10,
  "delay_before_typing_ms": 400,
  "newline_mode": "shift_enter",
  "pause_after_space_ms": 10,
  "pause_after_punctuation_ms": 80,
  "pause_after_newline_ms": 20,
  "pause_after_comma_ms": 60,
  "background_mode": true
}
```

| Поле | Смысл | Дефолт |
|------|-------|--------|
| `hotkey.macos` / `hotkey.other` | хоткей печати по платформе | Ctrl+V / Alt+V |
| `panic_hotkey` | полный сброс печати | Esc |
| `pause_hotkey` | пауза/продолжение (переключатель) | F8 |
| `type_and_send_hotkey` | опционально: напечатать **и нажать Enter**; уберите поле, чтобы выключить | выкл. |
| `average_speed_cps` | средняя скорость, симв/с. 42 — почти мгновенно; «живая» машинистка ≈ 14 | 42 |
| `speed_variance_percent` | сигма скорости, % от средней (нормальное распределение) | 10 |
| `delay_before_typing_ms` | пауза перед печатью — успеть переключить окно | 400 |
| `newline_mode` | `shift_enter` (в чатах не отправит) или `enter` | `shift_enter` |
| `pause_after_space_ms` | доп. пауза после пробела/таба | 10 |
| `pause_after_punctuation_ms` | после `. ! ? ; :` | 80 |
| `pause_after_comma_ms` | после запятой (поле опциональное) | 60 |
| `pause_after_newline_ms` | после перевода строки | 20 |
| `background_mode` | фоновая печать без фокуса — **только macOS** (на других ОС игнорируется) | true |

Модификаторы: `ctrl`, `alt`, `shift`, `meta` (алиасы: `control`, `option`,
`cmd`, `command`, `win`, `super`). Клавиши: `a`–`z`, `0`–`9`, `escape`,
`enter`, `space`, `tab`, `f1`–`f12`, а также символьные `= - [ ] ; ' \ , . / \``.

Задержка на символ = `1000 / N(average_speed_cps, σ=×variance%)` +
пауза по категории символа; скорость обрезается снизу (10% средней) и
задержка зажима в [8; 1500] мс — отрицательных/нулевых задержек не бывает.

Пример «медленной печати»: `"average_speed_cps": 5, "speed_variance_percent": 60`.

## Фоновая печать без фокуса (только macOS)

`"background_mode": true` — и печать идёт в окно, которое было в фокусе
в момент нажатия хоткея. Дальше фокус можно переключать куда угодно:
ставите длинный текст печататься в чат и уходите работать в редактор.

Как это устроено: события отправляются конкретному процессу через
`CGEventPostToPid` (текст — unicode-событиями, поэтому кириллица работает).
Проверка фокуса при возобновлении паузы в этом режиме не нужна — цель
«прибита» к PID. Ограничения: редкие приложения проверяют фокус сами и
могут игнорировать события; целевое окно приложения должно существовать.
На Windows/Linux режим не включается (конфиг не пройдёт валидацию) —
см. раздел «Известные ограничения».

## Лог

`autotyper.log` — в той же директории, что и `CONFIG.json` (append, без
ротации; при недоступном на запись каталоге — `~/.config/autotyper/`).
Записываются:
старт печати (длина текста, режим, цель), конец (сколько введено, чистое
время без пауз, средняя фактическая скорость, была ли пауза, был ли
сброс), события паузы/продолжения/отклонения возобновления, ошибки
буфера обмена и движка ввода. Короткие статусы дублируются в stderr.

## Автозапуск

### Linux: systemd (user unit)

`~/.config/systemd/user/autotyper.service` (пример — `examples/systemd/`):

```ini
[Unit]
Description=Autotyper — печать из буфера обмена по глобальному хоткею
After=graphical-session.target

[Service]
ExecStart=%h/.local/bin/autotyper
Restart=on-failure
RestartSec=3

[Install]
WantedBy=default.target
```

```bash
systemctl --user daemon-reload
systemctl --user enable --now autotyper
journalctl --user -u autotyper -f
```

### macOS: launchd

`~/Library/LaunchAgents/com.autotyper.plist` (пример — `examples/launchd/`):

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN"
  "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>Label</key><string>com.autotyper</string>
  <key>ProgramArguments</key>
  <array><string>/usr/local/bin/autotyper</string></array>
  <key>RunAtLoad</key><true/>
  <key>KeepAlive</key><true/>
  <key>StandardErrorPath</key><string>/tmp/autotyper.stderr.log</string>
</dict>
</plist>
```

```bash
launchctl load ~/Library/LaunchAgents/com.autotyper.plist
launchctl list | grep autotyper
```

Так как launchd запускает бинарник напрямую из `/usr/local/bin`
(каталог недоступен на запись без root), CONFIG.json и лог создаются в
запасном `~/.config/autotyper/`. Разрешение Accessibility выдаётся
самому `/usr/local/bin/autotyper`.

## Известные ограничения

### Печать кода в редакторах с авто-отступом

Отступы и переводы строк печатаются как есть, без борьбы с редактором.
Универсального способа «печатать посимвольно» в редактор, который сам
добавляет отступы и закрывает скобки, не существует — зрелые инструменты
признают то же ([espanso](https://espanso.org/docs/matches/) предупреждает
о «неожидаемых результатах», пользователи AutoHotkey и голосовые кодеры
на Talon отключают авто-отступы в редакторах). Практический рецепт: в
целевом редакторе отключите авто-отступ и автозакрытие скобок (VS Code:
`editor.autoIndent: none`, `editor.autoClosingBrackets: never`) — и текст
воспроизведётся байт-в-байт. В чатах и простых полях всё работает без
настроек.

Родственная напасть — **автокапитализация** (System Settings → Keyboard →
Text Input → Edit → «Capitalize words automatically»): первое слово
строки печатается с заглавной. Если видите «Ааа» вместо «ааа» — отключите
эту опцию; перехватить её со стороны autotyper нельзя.

* rdev только слушает события — подавить прохождение хоткея в приложение
  он не может: Ctrl+V/Alt+V дойдут и до целевого окна (в большинстве
  приложений эти сочетания ничего не делают). Esc при сбросе и F8 при
  паузе тоже попадают в окно: F8 в редких приложениях что-то делает
  (VS Code — переход к следующей диагностике); если это мешает —
  смените `pause_hotkey` в CONFIG.json.
* Фоновый режим (`background_mode`) реализован только на macOS: на Windows
  современные приложения игнорируют ввод, постящийся в чужое окно
  (PostMessage/WM_CHAR), на Linux/X11 тулкиты отбрасывают синтетические
  XSendEvent — «честного» фона там не сделать.
* Wayland не поддерживается (см. раздел Linux).
* Печать идёт в активное окно (или в выбранное — в фоновом режиме);
  следите, куда вводится текст, — на то есть `delay_before_typing_ms`,
  пауза и panic-хоткей.

## Структура кода

```
src/
├── main.rs     — точка входа, связка модулей, стартовые сообщения
├── config.rs   — конфиг: дефолты (с // комментариями в файле), вырезание
│                 комментариев, загрузка/создание, валидация
├── hotkey.rs   — rdev: разбор хоткеев, отслеживание модификаторов,
│                 пауза/сброс (AtomicBool), проверка фокуса при resume,
│                 запуск сеансов печати в отдельных потоках
├── typer.rs    — «человеческая» печать: SpeedModel (Normal), категории
│                 символов, newline-режимы, пауза/отмена в ожидании,
│                 KeySink — приёмник ввода (enigo | фоновый PID)
├── log.rs      — логгер в файл (append)
└── backend/    — платформенный слой: предупреждения, frontmost_pid
    ├── macos.rs   — + PidSink: CGEventPostToPid (фоновая печать)
    ├── windows.rs — frontmost_pid (GetForegroundWindow)
    └── linux.rs   — frontmost_pid (EWMH через x11)
```
